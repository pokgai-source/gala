# Roadbook v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (Jed chose inline execution). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Turn the Baguio roadbook photo-led and lighter on text. Make the map exact, suggest 2 stops (with EV
charging), and add Apple-style scrolling, flip-pad sections and a laptop tri-fold unfold.

**Architecture:**
- A GitHub Actions "assets" job does everything that needs the internet: OSRM, Overpass and Wikimedia Commons.
  It commits route lines, stop pins, photo candidates and resized WebP photos back to the branch.
- The build stays offline and renders the new data.
- Motion is CSS scroll-driven animations only.

**Tech Stack:** Node 22 ESM, `node:test`, `sharp` (WebP), Playwright (fold images, QA), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-10-roadbook-v3-photos-motion-design.md` (on top of the v2 spec).

## Global Constraints

- The v2 constraints still hold: no facts in templates, "Checked" on every fact, fixed road-sign colours,
  48 px tap targets, no sideways scroll at 360 px, both themes work, reduced motion respected.
- Allowed photo licences: CC0, Public domain, CC BY 2.0–4.0, CC BY-SA 2.0–4.0. A credit line shows wherever a
  photo shows.
- Facts get a `short` field of ≤90 characters. The full value moves behind "More". The "Checked" line stays
  visible.
- Budget: HTML + fonts + eager images ≤ 400 KB. Lazy images are excluded. HTML stays ≤ 150 KB.
- EV and stop data follow the source rules: operator or official sources, aggregators as leads only.
- Commits carry the session attribution lines. Branch `roadbook-v3`.

## Review Focus

1. **A photo entry with no `file` yet** (candidates only). The page falls back to the SVG art or no image, and
   the build doesn't fail. Test: Task 3.
2. **Overpass finds no match for a stop.** The approximate pin stays, `lnglatSource` is `"approximate"`, and the
   build warns. Test: Task 1.
3. **A long swipe row at 360 px.** It scrolls inside its own container; the page doesn't scroll sideways.
   Test: Task 5 (design check).
4. **Reduced motion.** All animated elements sit in their final, visible state. Test: Task 6.
5. **A photo without author or licence.** The build fails naming the photo id. Test: Task 3.

### Task 1: Assets job (route line, stop pins, photo candidates, photo prep)
**Files:**
- Create: `scripts/assets/{commons.mjs, osm.mjs, run.mjs}`, `scripts/assets.test.mjs`, `data/photos.json`,
  `.github/workflows/assets.yml`
- Modify: `package.json` (add `sharp`)

**Produces:**
- `commons.mjs`:
  - `allowedLicense(shortName) -> boolean`
  - `creditFrom(extmetadata) -> {author, license, licenseUrl}`, which strips HTML from `Artist`
  - `searchCandidates(query, n)`
  - `fetchOriginal(file)`
- `osm.mjs`:
  - `overpassQuery({brand, near, radius}) -> string`
  - `nearest(elements, near) -> {id, type, lnglat} | null`
  - `waypointHash(waypoints) -> string`
- `run.mjs`: traces the route lines, pins the stops, saves candidates, prepares the chosen photos. It logs
  every step.

- [ ] **Test first:**
  - `allowedLicense` accepts "CC BY-SA 4.0" and "Public domain", and rejects "CC BY-NC 2.0" and "Fair use".
  - `creditFrom` turns `<a href>Juan</a>` into "Juan".
  - `nearest` picks the closer of two elements, and gives `null` for an empty list.
  - `waypointHash` is stable and changes when a point changes.
  - `overpassQuery` contains `amenity"="fuel"` and `around:1500,<lat>,<lng>`.
- [ ] **Implement, then push.** The workflow runs on GitHub. Read the committed `docs/photo-candidates/*` with
  `gh api` and look at the thumbnails.
- [ ] **Pick photos.** Set `file` per entry (Ruling notes), push, and the job commits the WebP files plus
  credits. Pull.

### Task 3: Payload and photos in the payload
**Produces:**

- [ ] **Tests:**
